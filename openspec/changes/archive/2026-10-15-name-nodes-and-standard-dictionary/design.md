## Context

- The Nodes table of Commission (`commNodeTable` in `commission.js`, and the with-config table in `app.js`) fills the Device column only from `S.scanResult`. Nodes that are only heard have an empty cell. The scan itself already reads 0x1018:1-4, 0x1000 and 0x1008 per node, both in the PC-direct client (`localbus/client.py` `_scan_one`) and in the plugin (`network_diag.cpp`), and returns `device_name`.
- Manual SDO reads (`/api/online/sdo_read`) work on both connection kinds without force or Allow changes.
- The Object dictionary, Parameters and SDO panel get their objects from `nodeSource(id)`: the config node's EDS, or an EDS opened for a scanned node (`S.onlineEds`). Without one, `odPanel` and `paramsPanel` show `noEds(id)` and `sdoPanel` shows an empty picker. `params.py` builds `od_entries` from a parsed EDS (`ctx.eds`).
- Built-in notes for CiA 301, 401 and 402 already exist in `builtin_notes/` and are merged by object index, so standard objects get their notes for free.

## Decisions

1. **Identity read per heard node, driven by the page.** A new `/api/online/identify {node, port}` (module `identity.py`) reads, in this order, 0x1018:1 (as the probe; a timeout ends it with `answered: false`, an abort still counts as an answer), 0x1018:2-4, 0x1000, 0x1008, 0x1009, 0x100A, each with a 300 ms timeout, through the connection's manual SDO read. It returns the scan's fields (`vendor_id`, `product_code`, `revision_number`, `serial_number`, `device_type`, `device_name`) plus `hardware_version`, `software_version`, and `eds_matches` from the EDS index.
   The page (`identity.js`) keeps the answers for the connection and asks for one node at a time from the status poll: a node heard for the first time, a node heard again after not answering (boot-up), and a node leaving STOPPED whose identity is still missing. A disconnect, a new connection or closing the folder forgets them, so a reload reads again (a few SDO reads per node). A scan result for a node counts as read. Strings are decoded as the scan does (Latin-1, up to the first NUL, control characters as spaces, at most 128 characters) and shown as text, never as HTML.
   Alternatives: reading in the status poll on the server (runs with no page open, harder to test); running a full scan automatically (probes 127 IDs and asks for force on a running bus).
2. **Device text fallback order.** 0x1008 → product name of the first EDS match → profile name from 0x1000 low 16 bits (301 → "CiA 301 device", 401 → "CiA 401 I/O device", 402 → "CiA 402 drive", 404 → "CiA 404 measuring device", 406 → "CiA 406 encoder", 418/419 battery and charger; any other → "CiA <n> device") → "vendor 0x… product 0x…". The muted line after it gives whatever of vendor (with the EDS VendorName when matched), product and profile is not already the main text. The full name is kept; the cell wraps rather than cutting it.
3. **Standard dictionary as a table, read as EDS text.** `standardod.py` holds the CiA 301 communication objects (0x1000-0x1029 that CiA 301 defines, 0x1200 server SDO, RPDO and TPDO communication and mapping objects) and the CiA 401 and CiA 402 standard objects, with their names, data types, access and PDO mappable flags. A table, not EDS files, because the PDO objects and arrays repeat; it is written out as EDS text (`[DeviceInfo] ProductName=Standard CiA 301 objects …`) and parsed with the existing EDS reader, cached per profile and PDO count. So the OD tab, reads, watch, value formats, notes, editing with range check and the SDO picker all work unchanged. Entries have no defaults (a standard has no single default, so "≠ default" never shows); only 0x1000 carries the profile number, which picks the built-in profile notes and is not shown. The page sends `{node, standard: true, device_type, rpdos, tpdos, port}`; every other parameters route refuses such a source ("needs the device's EDS").
   Alternatives: EDS files in the package (hundreds of repeated sections); fetching the device's EDS from 0x1021 (few devices have it; out of scope).
4. **Variable-length objects.** The table gives arrays such as 0x1003, 0x1010, 0x1011, 0x1016 and the PDO mapping objects their full sub-entry range (CiA 401 arrays up to 64 blocks or channels). The OD tab shows an ARRAY's sub 0 and sub 1 and a RECORD's every sub until sub 0 has been read, then sub 1 to the read count; sub-entries past it are not drawn, not marked missing. Read on such an object reads sub 0 first. For a configured node with an EDS nothing changes.
5. **Missing objects.** For standard entries, aborts 0x06020000 and 0x06090011 are shown as "not on this device" instead of the generic "not readable" text. A new filter **Hide objects the device lacks** is on by default for a standard dictionary and hides an entry, and an object whose entries are all lacking, once its read said so. **Read all** on the standard dictionary reads sub 0 of each object first and skips the rest of an object that does not exist, then probes RPDO and TPDO 5 onwards (communication object sub 0) until the first that does not exist, adding the found ones to the tree. This keeps Read all on a small device to tens of reads, not hundreds.
6. **Where the EDS still wins.** As soon as a node has an EDS (config, match, pick), its EDS replaces the standard dictionary and the cached entries are dropped; the top line of the standard view offers exactly that. Parameters (Back up, Compare, Restore, Store) need the device's own EDS: the tab says "Back up, compare and restore need the device's EDS" and offers the same EDS pick.
7. **Change EDS… as a button and a dialog.** One small button after the file name opens the page's dialog with the other library matches for the node's identity, **Pick EDS file…**, then **Clear EDS** or, for a node only added from an EDS and not heard, **Remove node**. A dialog rather than a drop-down menu because the Nodes table is redrawn with every status answer, which would close an open menu. Changing or clearing updates `S.onlineEds`, `S.onlineEdsName` and `commNodes()` together, drops the node's cached `od_entries`, read values, compare marks and watch list of the old EDS, and writes a Commissioning log line ("Change EDS a.eds → b.eds"). The EDS column now shows the file name (it showed the device's name when the scan had one). It changes nothing on the device or in a config. A config node's EDS is not changed here: Configure's node page owns it and the existing **Use matching EDS** in the Compared cell stays the way to swap it from Commission.
8. **No change to the plugin, contract or deploy.** The runtime path already answers manual SDO reads for any node, configured or not.

## Risks / Trade-offs

- Identity reads on a bus with another master can meet that master's own SDO traffic to the same node (both use 0x600 + node ID). This is the same risk as a manual read today; reads are few, one at a time, and a timeout leaves "no SDO answer" with a **Read again** link, nothing more.
- A device that answers 0x1008 with a long or odd string (non-printable bytes): control characters are replaced and the text is shown in full but wrapped; the scan already accepts such strings.
- The standard dictionary can show objects a device lacks until they are read. The top line says so, and Read all hides them.
- Writing through the standard dictionary uses CiA 301 types and access, which a device may define more narrowly; the device's abort is shown as today.
- The standard table must stay free of vendor or device names (public repo guard); it only holds CiA standard object names.

## Context

Today the README and `docs/install-pc.md` give `powershell -ExecutionPolicy ByPass -c "irm https://raw.githubusercontent.com/tonihoohoo/canworks/main/scripts/install-pc.ps1 | iex"` for Windows. When uv is not found, `install-pc.ps1` runs `powershell -NoProfile -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"` as a child process. Options and the runtime and bridge installers use `& ([scriptblock]::Create((irm <url>)))`. Defender flagged a run of the README line on a Windows 11 PC; the detection name was not kept. The CI Windows job runs the script with `-File` and with uv already present (setup-uv), so the uv download route never runs in CI.

Defender inspects PowerShell in two places: AMSI scans every script and script block before it runs (whether it came from a file or `iex`), and behaviour monitoring watches process command lines. Downloaded code piped into `iex`, `ExecutionPolicy Bypass` on a command line, and one PowerShell starting another to download code are all common in droppers, so each raises the score. Removing them is the only thing we control; signing the scripts is a separate, later step.

## Goals / Non-Goals

**Goals:** no `iex`, script-block creation or nested PowerShell anywhere in the Windows install path; uv installed from a checked file; the released script is what users run; per-OS README blocks that copy cleanly; a CI guard so the patterns do not come back.

**Non-Goals:** Authenticode signing of the scripts (needs a code-signing certificate; SignPath Foundation is free for open source and can follow); reporting the detection to Microsoft as a false positive (Toni: nothing posted outside the project); rewriting the macOS and Linux lines beyond their URL (`curl | sh` is not what was flagged, and is the usual form there); a standalone `.exe` or MSI installer.

## Decisions

- **uv from its release zip, not winget, inside the script.** `install-pc.ps1` picks `uv-aarch64-pc-windows-msvc.zip` when `$env:PROCESSOR_ARCHITECTURE` is `ARM64`, else `uv-x86_64-pc-windows-msvc.zip`, downloads it and `<zip>.sha256` from `https://github.com/astral-sh/uv/releases/latest/download/` (overridable by `CANWORKS_UV_DOWNLOAD` for tests and mirrors), compares `Get-FileHash -Algorithm SHA256` with the first field of the `.sha256` file, and `Expand-Archive`s into a temporary folder, then copies `uv.exe`, `uvx.exe` and `uvw.exe` into `%USERPROFILE%\.local\bin`. That is the folder uv's own installer uses, so `Find-Uv` and `uv tool update-shell` work unchanged and a later uv self-update works. On mismatch it stops with "uv download did not match its checksum" and copies nothing. Alternative considered: `winget install astral-sh.uv`. Rejected for the script because winget may be missing (LTSC and IoT builds, which this project has met), can stop on a source agreement prompt, and puts uv in `%LOCALAPPDATA%\Microsoft\WinGet\Links`, which the current session's PATH does not have. It stays as the first manual route in `docs/install-pc.md`.
- **`RemoteSigned`, not `Bypass`, on the documented line.** The line downloads to `$env:TEMP\install-pc.ps1` with `irm ... -OutFile`, then runs `powershell -NoProfile -ExecutionPolicy RemoteSigned -File` on it, joined with `;` so it stays one line. `Invoke-RestMethod -OutFile` does not mark the file as downloaded from the internet, so `RemoteSigned` runs it; it does not switch policy checks off for everything as `Bypass` does. If the hardware check (task 5) shows `RemoteSigned` refusing the file on Windows PowerShell 5.1, the fallback is `Unblock-File` before running, and only then `Bypass` with `-File`.
- **Scripts as release assets, on every system.** `gh release create` also uploads the three `.ps1` and the three `.sh` install scripts from the released commit, so Windows, macOS and Linux all run the released script (Toni, 2026-10-20). The lines use `https://github.com/tonihoohoo/canworks/releases/latest/download/<script>`. Release asset downloads redirect, so the `.sh` lines keep `curl -LsSf` (`-L` follows it). Release retention never deletes the latest release, so this URL always works. The `raw.githubusercontent.com/.../main/scripts/...` URLs keep working for anyone with an old line, and the scripts still install any `-Version`, also releases older than this change.
- **The guard is a plain text test.** `test_install_scripts.py` reads every `scripts/*.ps1` (comments stripped) and the Windows lines in README.md, `docs/*.md` and `tools/deploy/release-notes.md` (lines that hold `.ps1` or `powershell`) and fails on `iex`, `Invoke-Expression`, `scriptblock]::Create`, `-EncodedCommand`, `ExecutionPolicy Bypass` (any case), and on `powershell`/`pwsh` started from inside a script. It names the file and line.
- **README layout.** Each install step becomes a lead sentence, then one fenced block per system, each block preceded by a short label in bold ("**Windows (PowerShell)**", "**macOS and Linux**", "**On the PLC (Linux)**", "**From Windows over SSH**"). The `canworks-config` start line goes after the install blocks as its own block. No block mixes systems; trailing alignment comments go. `docs/install-pc.md` already has per-OS blocks; `install-stock.md` and `modbus-bridge.md` get the same split where they mix.
- **CI runs the zip route.** The PC tools Windows job runs the installer a second time in a step whose PATH has no uv and whose `USERPROFILE` is a fresh folder, so the uv zip download, checksum and extraction run for real on each version bump. The job already runs only on version bumps, so CI time on pull requests does not change.

## Risks / Trade-offs

- [The cause is inferred] → task 1 asks Toni to read the detection name from Windows Security's Protection history if it is still there; task 5 runs the new line on the same PC with real-time protection on. If Defender still flags it, the next step is signing, not more rewording.
- [uv's zip layout or asset names change] → the CI step above catches it on the next version bump, and the error names the URL that failed.
- [`releases/latest` points at a release without the assets] → only possible for the window between this change merging and its release; the merge triggers that release, and the old raw URL still works meanwhile.
- [Two-step line is longer] → still one line to copy, in its own block.

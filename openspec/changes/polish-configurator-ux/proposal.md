## Why

A UI/UX review of the configurator on 2026-10-08 (see the project notes `research/ui-ux-review-2026-10-08.md`: 56 screenshots, axe-core on every view, interaction probes, two code audits) found that the page is right on layout, labels, defaults and problem text, but wrong on a set of interaction patterns that every desktop tool is expected to get right. Two of them are bugs a user hits by clicking through the node list: the hover-only "Export DCF" button sits under the click point of a node item, so a click runs an export instead of opening the node, and a failed export then doubles the Problems list. The rest: dialogs whose default and focused button is the destructive one, removals with no undo, a node list and problem list that the keyboard cannot reach, tabs with the wrong ARIA, nothing announced to screen readers, a header with nine buttons before Save, node pages 3,800 to 5,000 px tall, "null" rendered as text, and config paths and schema wording leaking into messages.

None of it needs a redesign. This change fixes the bugs and brings the interaction patterns in line, with a test that keeps them there.

## What Changes

- **Bugs**: Export DCF leaves the node list item (it moves next to Remove node on the node page and into the Export menu); export checks replace the problem list instead of prepending to it and recompute the counts; the literal "null" in Variable declarations and the Online node overview goes; "Commission a device" hides the config header actions, the config side bar entries and the Problems pane; the New project dialog's checkbox sits inline with its label; fields the runtime may omit no longer render "undefined".
- **Dialogs and destructive actions**: the safe button (Cancel, or the non-destructive choice) is the default and takes focus in every confirmation; the destructive button is styled as such and never first; Escape cancels. Row removals (PDO entry, startup SDO, SDO variable, slave object, descriptor object, gateway route) get an Undo in the message bar backed by a draft snapshot stack, and Ctrl+Z / Ctrl+Shift+Z undo and redo edits of the draft. Pre-operational asks like Stop does. Trace Clear says the recording is lost unless saved, and leaving the page with an unsaved recording asks.
- **Keyboard and assistive technology**: node list items, problem list items and clickable rows (online nodes, scan, simulation devices) become focusable and act on Enter and Space; one shared tabs helper gives the Trace, Online node and Simulation tabs `role=tablist`, `aria-selected`, `aria-controls` and arrow keys; the problem count, job progress lines and the online connection line are live regions and the red message bar is an alert; `#problems` and the inspector box stop being nested `<aside>`s; heading levels no longer skip; action columns get a hidden header; `--ok` and the inspector tints meet 4.5:1; inputs and small buttons reach 24 px; `:focus-visible` uses the accent colour; the trace graph series colours follow the theme.
- **Header and node page**: exports (all DCFs, DBC with its frame choice, documentation, this node's DCF) move into one "Export" menu, and "Move into project…" and "New editor project…" into a "Project" menu, so the header is Reload, Close, Project, Export and Save; a node page gets a sticky section index (Node · Supervision · PDOs · Startup SDOs · SDO variables), empty Startup SDO writes and SDO variables sections open collapsed, and "Map an object" becomes an "Add entry…" picker inside each PDO block. Editing the node name updates the side bar as you type; adding a node moves focus to its name field; "Pick EDS file…" on the Scan page navigates to the new node like "Add node from EDS…" does.
- **Feedback and wording**: the empty config's problem reads "No nodes yet. Add a node from its EDS, or turn on Online access for a scan-only configuration."; trace and Frame lab decoding notes use the same humanised wording as the Problems pane, without the config path; unhandled server errors become one sentence pointing at the configurator's terminal; Save, the exports, Move into project and Add node disable their button and show "…ing" while the request runs; a dropped online connection greys the node table and shows the age of the last data; the "runtime runs a different configuration" note names the deploy command; the Save button is "Saved" and disabled when clean, "Save" when dirty, with the error count in the Problems pane and the reason in the button's tooltip; tooltip-only controls get visible or accessible names (Trace "Save to traces folder" / "Download", "Format for saving" / "Format for download", lane selects); "Send both" in the Frame lab becomes "Run both"; one pass over Remove/Add labels and the node/device/runtime/PLC vocabulary.
- **Tests**: axe-core (vendored, MPL-2.0) runs in the layout browser test over every view and fails on new critical or serious violations; browser tests for the node list click target, dialog default focus, undo, keyboard reach of the lists, the Export menu, the empty-config message and the commissioning header.

## Capabilities

### New Capabilities
- none

### Modified Capabilities
- `canopen-configurator`: new requirements for keyboard access and announcements, dialog defaults, undo, header menus, node page sections, busy states and the accessibility check; modified requirements for Export DCF files (where the per-node action lives), Scan the bus and add nodes (navigate to the new node), Manual SDO and NMT (Pre-operational confirms), Readable problem messages (no path in trace and Frame lab notes, empty-config wording), Message bar (alert and undo), Online view (stale data, upload hint), Trace view (tab semantics, Clear wording, unsaved recording), Commission a device without a config (no config UI), Frame lab view (label).

## Impact

- `tools/deploy/openplc_canopen_deploy/configurator/static/`: app.js (node list, problems, dialogs, undo stack, menus, node page sections, busy states, save label, live regions), trace.js (tabs, toolbar labels, Clear, series colours), sim.js (rows, tabs), explain.js (aside, label), index.html (header menus, landmarks), style.css (focus ring, target sizes, menu, section index, stale state, `--ok`). `server.py`: humanised decoding notes, error sentence. No plugin, runtime, schema or config-format change; no new runtime dependency.
- Tests: `tests/test_configurator_layout.py` gains the axe run (`tests/data/axe.min.js`), new `tests/test_configurator_ux_page.py`; existing page tests that click `#node-list li` or rely on the header buttons are adjusted.
- Docs: `docs/configurator.md` (header menus, undo, keyboard), README (configurator bullet). Deploy tool minor version bump.
- Non-goals: moving the online connection settings to their own side bar entry, redesigning the narrow (under 1100 px) bar, a glossary document, a per-field change history. These are noted in the review for later.

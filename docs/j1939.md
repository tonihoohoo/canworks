# J1939 networks

A network with `"protocol": "j1939"` makes canworks an ECU on a J1939 bus (SAE J1939 on 29-bit CAN identifiers, as in vehicles and mobile machines). It claims a source address, receives parameter groups (PGNs) from other ECUs into `%I` locations, sends PGNs from `%Q` locations, answers requests and asks other ECUs for PGNs. J1939 and CANopen networks can share one config file (`schema_version` 2), each on its own interface.

The bridge uses the Linux kernel's J1939 stack (`CAN_J1939` sockets): the kernel handles the transport protocol (BAM and RTS/CTS, messages up to 1785 bytes), and the bridge does the address claim, the signals and the process image. The PC tools use [can-j1939](https://github.com/juergenH87/python-can-j1939) for the simulator.

[`examples/j1939`](../examples/j1939) holds a complete config and its DBC file: a PLC at address 128 that reads pressures, a temperature and a level from an engine ECU at address 0, asks it for component data (a 40-byte PGN) once a second, and sends a speed setpoint and an operating mode.

## The kernel module

J1939 needs the kernel module `can-j1939`. `scripts/install-bridge.sh` loads it and lists it in `/etc/modules-load.d/canworks-j1939.conf`, so it loads at every boot. Most Debian-based device images ship the module. On Ubuntu it is in `linux-modules-extra-$(uname -r)`.

Without the module a J1939 network does not start and the log says so ("J1939 needs the can-j1939 kernel module (modprobe can-j1939)"); its state byte reads 3 (no bus). The bridge retries every 5 s, so loading the module later is enough. CANopen networks in the same config run regardless.

A bridge built without J1939 (`install-bridge.sh --without-j1939`) refuses a config with a J1939 network: "J1939 is not built into this canworks (built with: canopen)". `--without-canopen` builds J1939 only, without Lely or dcfgen.

## The config

```json
{
  "name": "machine",
  "protocol": "j1939",
  "adapter": { "type": "socketcan", "interface": "can0", "bitrate": 250000 },
  "j1939": {
    "ecu": {
      "name": { "identity_number": 1234, "function": 130, "arbitrary_address_capable": true },
      "address": 128,
      "address_range": [128, 135],
      "state_location": "%IB200",
      "address_location": "%IB201"
    },
    "dbc": "machine.dbc",
    "rx": [ { "pgn": 65280, "name": "Pressures", "source": 0, "timeout_ms": 300, "status_location": "%IX202.0",
              "signals": [ { "name": "Pressure", "start_bit": 0, "length": 16, "scale": 0.1, "unit": "bar",
                             "iec_location": "%IW210", "valid_location": "%IX202.1" } ] } ],
    "tx": [ { "pgn": 65281, "name": "Setpoints", "period_ms": 100,
              "signals": [ { "name": "Setpoint", "start_bit": 0, "length": 16, "iec_location": "%QW210" } ] } ],
    "requests": [ { "pgn": 65282, "destination": 0, "period_ms": 1000 } ]
  }
}
```

J1939 is usually 250 kbit/s (500 kbit/s on newer machines). The adapter settings are the same as for CANopen ([config.md](config.md)).

### The ECU

| Field | Meaning |
|---|---|
| `name` | The 64-bit NAME, by field: `identity_number` (21 bits), `manufacturer_code` (11), `ecu_instance` (3), `function_instance` (5), `function` (8), `vehicle_system` (7), `vehicle_system_instance` (4), `industry_group` (3), `arbitrary_address_capable`. Fields left out are 0. A lower NAME wins an address contention. |
| `address` | The preferred source address, 0..253. |
| `address_range` | `[low, high]`: where the ECU may move when it loses its address to a lower NAME. Needs `arbitrary_address_capable`. |
| `state_location` | Byte input: 0 claiming, 1 claimed, 2 cannot claim, 3 no bus. |
| `address_location` | Byte input: the address held, 254 while none is. |

At start the network asks every ECU for its claim, listens 250 ms, then claims `address` unless an ECU with a lower NAME holds it. The claim stands after another 250 ms; until then nothing else is sent. Against a lower NAME, an arbitrary-address-capable ECU moves to the next free address of its range; otherwise, or with the range used up, it sends Cannot Claim and stays silent (state 2). A contending claim from a higher NAME is answered with our claim, and requests for the address claim are answered. In state 2 the answer is Cannot Claim, sent after a pseudo-random wait of 0 to 153 ms (J1939-81) drawn from a generator seeded with the NAME.

When the interface goes down, the adapter is unplugged or the controller reaches bus-off, the state goes to 3, inputs hold their values while every `status_location` and `valid_location` goes FALSE, and the network claims its address again when the bus is back.

### Received PGNs (`rx`)

| Field | Meaning |
|---|---|
| `pgn` | 0..0x3FFFF. A PDU1 PGN (PDU format below 0xF0) has its low byte 0; it is taken when sent to our address or to global. |
| `source` / `source_name` | Take the PGN only from this source address, or only from the ECU with this NAME (`source_name_mask`: the NAME bits to compare). Without either, from any ECU. |
| `timeout_ms` | 0: no supervision. Otherwise `status_location` goes FALSE when nothing arrived for this long, and TRUE again with the next message. Values hold their last value meanwhile. |
| `status_location` | Bit input: TRUE while the PGN arrives. |
| `signals` | See below. |

### Sent PGNs (`tx`)

| Field | Meaning |
|---|---|
| `pgn`, `destination` | The PGN, and for a PDU1 PGN the destination address (default 255, global). |
| `priority` | 0..7, default 6. |
| `period_ms` | Send every `period_ms`. 0: send when a value changes (no faster than `min_gap_ms`) and when requested. |
| `min_gap_ms` | With `period_ms` 0: the least time between two sends on change, default 0. A change within the gap goes out when it has passed. |
| `length` | Bytes; default the smallest length of at least 8 that holds every signal. Over 8 bytes the kernel sends with the transport protocol. |

Values come from the last Modbus write; nothing is sent before a writer client's first write ([outputs and the watchdog](modbus-bridge.md#outputs-the-watchdog-and-client-loss)). Unused bits are sent as 1 (J1939 "not available"). A change the interface refuses to send (a full transmit queue) does not count as sent: the PGN goes out with its current values once the interface takes frames again.

### Requests

A Request (PGN 59904) for one of the network's `tx` PGNs, to our address or to global, is answered with the current values; a request to our address for any other PGN gets a NACK. Before the program's first scan has written the outputs, requests for `tx` PGNs get no answer. A PDU1 PGN is answered as J1939-21 says: to the requester for a Request to our address, to global for a global Request. An answer to the requester only does not count as the send to the entry's own `destination`, so a changed on-change value still goes there. Each `requests` entry asks `destination` (an address, or 255 for every ECU) for its PGN every `period_ms` (100 ms or more); the answer is received like any other PGN when an `rx` entry names it.

Requests for the same PGN from the same ECU are answered at most once every 50 ms; requests in between are ignored. This also holds for NACKs and for requests for the address claim, except those from the null address (254) sent by ECUs that are still claiming.

### Signals

| Field | Meaning |
|---|---|
| `start_bit`, `length` | As in a DBC file: the least significant bit for little byte order, the most significant one for big. 1..64 bits. |
| `byte_order` | `"little"` (default, the J1939 order) or `"big"`. |
| `signed` | Two's complement; the value reaches the PLC sign-extended. |
| `scale`, `offset`, `unit` | For the tools only (trace, configurator, the HTML document). |
| `iec_location` | `%I` for a received signal, `%Q` for a sent one, wide enough for `length` (X 1 bit, B 8, W 16, D 32, L 64). |
| `valid_location` | Received signals: a bit input that is FALSE while the signal arrives as not available or error ([below](#not-available-and-error-values)). The value location keeps its last value then. On a PGN with `timeout_ms` it also goes FALSE when no message carried the signal for that long (a multiplexed page that stopped). |
| `multiplexer`, `mux` | Multiplexing, as for raw messages; see [Multiplexed PGNs](#multiplexed-pgns). |

### Not available and error values

A received signal's `valid_location` goes FALSE for these raw values (J1939-71), and the value location keeps its last value:

| Signal | Error | Not available |
|---|---|---|
| unsigned, 8 bits | 0xFE | 0xFF |
| unsigned, 16 bits | 0xFE00-0xFEFF | 0xFF00-0xFFFF |
| unsigned, 32 bits | 0xFE000000-0xFEFFFFFF | 0xFF000000-0xFFFFFFFF |
| unsigned, other lengths of 2 bits or more | all ones minus one | all ones |
| signed, or 1 bit | none | none |

A signed signal reads -1 and -2 as values. The PC simulator ([below](#simulator)) follows the same rule: its ramps stay in the valid range and its received messages mark such values ("Setpoint=65104 (error)").

### Multiplexed PGNs

A PGN can carry different signals in the same bytes, picked by a switch signal (the DBC's `M`, or `mNM` with `SG_MUL_VAL_` for nested switches). The fields and rules are those of raw messages ([raw-can.md](raw-can.md#multiplexed-messages)): a switch has `"multiplexer": true`, a dependent signal has `"mux": { "on": "Page", "values": [1, [4, 7]] }`, and signals on different pages may share bits.

A received multiplexed PGN, also one that arrives through the transport protocol, updates its switches, its page's signals and the signals of every page; the other signals keep their values. A switch value with no page counts as `unknown_pages` in the diagnostics status. A sent PGN with a switch has `pages`: `program` (default; the switch has an `iec_location` and the program picks the page), `all` (every page each period, the bridge sets the switch) or `rotate` (one page per period). A request for the PGN is answered with every page in `all`, the next page in `rotate` and the program's page in `program`. `all` and `rotate` take at most 64 pages.

Values reach the PLC raw. The program scales them with the signal's `scale` and `offset`:

```
pressure_bar := UINT_TO_REAL(canworks.machine_Pressure) * 0.1;   (* x 0.1 + 0 bar *)
```

## Diagnostic messages

A J1939 network handles the trouble codes of SAE J1939-73. A trouble code (DTC) is an SPN (what failed), an FMI (how it failed) and an occurrence count (OC). Every ECU broadcasts its active codes and warning lamps once a second in DM1 (PGN 65226); service tools read previously active codes with DM2 and clear codes with DM3 and DM11, and flashing tools quiet the bus with DM13.

The network collects every ECU's DM1, of any length, without any config. `diagnostics` in the `j1939` object maps them to the program and gives the PLC codes of its own:

```json
"diagnostics": {
  "rx": [
    { "source": 0, "timeout_ms": 3000, "status_location": "%IX207.0", "lamps_location": "%IB220",
      "flash_location": "%IB221", "count_location": "%IB222", "dtcs_location": "%ID220", "dtcs": 4 }
  ],
  "dtcs": [
    { "spn": 520192, "fmi": 3, "lamps": [ "amber" ], "active_location": "%QX206.0" },
    { "spn": 520193, "fmi": 1, "lamps": [ "red" ], "flash": "fast", "active_location": "%QX206.1" }
  ],
  "lamps_location": "%QB207",
  "clear_location": "%IB223"
}
```

### Other ECUs' codes (`rx`)

Each `rx` entry watches one ECU, by `source` address or by `source_name` (with an optional `source_name_mask`), and needs at least one location. Every DM1 from it sets, by the next scan:
- `lamps_location` and `flash_location` (`%IB`): the lamp and flash bytes as on the wire
- `count_location` (`%IB`): the number of codes, 0 when the ECU reports none, at most 255
- `dtcs_location` (`%ID`) with `dtcs` (1..32): the first codes in message order, one double word each, unused slots 0
- `status_location` (`%IX`): TRUE; FALSE when no DM1 came for `timeout_ms` (default 3000, 0 switches the check off), while the other locations keep their last values

A code reaches the program as one `UDINT`: SPN + FMI × 2^19 + OC × 2^24 + CM × 2^31. SPN 520192, FMI 3, OC 2 reads as `16#021FF000`. `J1939_DTC_SPLIT` and `J1939_DTC_MAKE` in the `canworks` library take it apart and build it. A code with the old SPN conversion method (CM set) is passed on unchanged and logged once per ECU.

The lamp byte holds two bits per lamp: MIL in bits 7-6, red stop lamp in 5-4, amber warning lamp in 3-2 and protect lamp in 1-0, each 00 off, 01 on, 11 not available. The flash byte uses the same places: 00 slow flash, 01 fast flash, 11 no flash.

### The PLC's own codes (`dtcs`)

Each `dtcs` entry is one code of the PLC (`spn` 0..524287, `fmi` 0..31), active while its `active_location` bit is TRUE, with the lamps it lights (`mil`, `red`, `amber`, `protect`) and optionally `flash` (`slow` or `fast`). `lamps_location` (`%QB`) sets lamps directly in the DM1 layout. With codes or `lamps_location`, the network sends DM1 every second once its address is claimed, and once more as soon as a code or the lamps change (at most once a second). Each code's occurrence count rises when its bit goes TRUE (up to 126). A code that goes inactive moves to the previously active list, which lives in memory only and is empty after every start.

The network answers requests for DM1 and DM2. A request for DM3 clears the previously active list; DM11 also resets every occurrence count, and codes still active stay with OC 1. A clear sent to the PLC's address gets an ACK, a global one does not. `clear_location` (`%IB`) counts every clear, so the program sees that a tool cleared its codes. With `"accept_clear": false` the PLC answers clears to its address with NACK and ignores global ones. DM22 (clear one code) is answered with its NACK.

### DM13

A DM13 that tells the current data link to stop broadcasts suspends the PLC's DM1 and every `tx` entry with a `period_ms`, until a DM13 says start or 6 s pass without another stop or hold. Address claims, request answers and on-change sends go on. `"dm13": false` ignores DM13.

### Trouble code blocks

`J1939_DM_READ` gives the program any ECU's codes without a mapping: with `PREVIOUS` FALSE the latest DM1 the network received from `SOURCE`, with `PREVIOUS` TRUE the answer to a Request for DM2. `J1939_DM_CLEAR` sends a Request for DM3 (`PREVIOUS_ONLY` TRUE) or DM11 to `DESTINATION` (255 for all) and is `DONE` on the ACK. Both have the `EXECUTE`/`BUSY`/`DONE`/`ERROR` handshake of the CAN frame blocks:

```
VAR
    rd : J1939_DM_READ;
    codes : ARRAY[0..31] OF UDINT;
    split : J1939_DTC_SPLIT;
END_VAR

rd(EXECUTE := read_now, NETWORK := 0, SOURCE := 0, DTCS := codes, LINK := canworks.link);
IF rd.DONE AND rd.COUNT > 0 THEN
    split(DTC := codes[0]);   (* split.SPN, split.FMI, split.OC *)
END_IF;
```

`TIMEOUT` defaults to 1 s. The `ERROR_ID` values are those of all J1939 blocks ([Error IDs](#error-ids)).

### Tools

`canworks-diag dm list` shows every ECU's lamps and codes and the PLC's own, `dm read --address 0` reads DM2 and `dm clear --address 0 --force` clears (`--previous` for DM3 only; through the PLC only with the diagnostics' `allow_changes`); through the PLC or straight on a USB adapter, where the PC claims service tool address 249 ([diagnostics.md](diagnostics.md#trouble-codes-dm)). The configurator edits `diagnostics` on the J1939 network page and shows the codes in the **Faults** panel of the online view. The trace decodes DM1, DM2, DM3, DM11, DM13 and DM22 with the FMI text and the SPN name from the DBC, and the frame inspector explains a code's four bytes. The simulator plays a faulty ECU with a `dtcs` scenario ([examples/j1939/engine-faults.json](../examples/j1939/engine-faults.json)).

Freeze frames (DM4, DM25), emissions messages, memory access (DM14-DM16) and sending DM22 are not supported. SPN names come only from your DBC.

## Program blocks

The [`canworks` function block library](plc-library.md) lets the program send, receive and request any PGN, beside what the config maps to locations. Install and enable it as [plc-library.md](plc-library.md#install-and-enable) describes. The blocks work through the bridge's [mailboxes](plc-library.md#the-mailboxes): `J1939_SEND`, `J1939_REQUEST`, `J1939_FIND_ECU` and the trouble code blocks need a request mailbox, `J1939_RECEIVE` also the receive mailbox, `J1939_ECU_INFO` network info. Every block has `NETWORK : USINT` (the network's place in `networks`, from 0), the in-out `LINK := canworks.link` and the outputs `ERROR` and `ERROR_ID`; message data is an in-out `ARRAY[0..1784] OF BYTE`, so one buffer holds the longest message. The configurator's **Copy as ST call** on an `rx` or `tx` entry writes the calls for that PGN ([configurator.md](configurator.md#j1939-networks)). `J1939_GET_BITS` and `J1939_SET_BITS` work in little-endian (J1939) order, so a big-endian signal gets a comment naming it instead of a call.

ST functions: `J1939_GET_BITS(DATA, START_BIT, BIT_LENGTH, SIGNED) : LINT` and `J1939_SET_BITS(DATA, START_BIT, BIT_LENGTH, VALUE) : BOOL` read and write a signal anywhere in the 1785 bytes, little-endian as J1939 sends signals (`BIT_LENGTH` 1..64; `J1939_SET_BITS` returns FALSE and writes nothing for bits outside the array). `J1939_NAME_MAKE` makes a NAME from its fields (`IDENTITY_NUMBER`, `MANUFACTURER_CODE`, `ECU_INSTANCE`, `FUNCTION_INSTANCE`, `ECU_FUNCTION`, `VEHICLE_SYSTEM`, `VEHICLE_SYSTEM_INSTANCE`, `INDUSTRY_GROUP`, `ARBITRARY_ADDRESS_CAPABLE`), and the block `J1939_NAME_SPLIT` splits one; they pack as the config's `ecu.name` does.

- **Sending.** `J1939_SEND` and `J1939_REQUEST` have the `EXECUTE` handshake ([plc-library.md](plc-library.md#handshakes)); `DATA` is taken as it is in the call with the rising edge. A message goes out from the address the network holds when it is sent, through the kernel's J1939 stack: up to 8 bytes as one frame, above that by BAM (global) or RTS/CTS (to an address). `DONE` comes when the kernel has taken a single frame, and when the transport protocol session has completed for a longer one. `TIMEOUT` `T#0s` means 1 s up to 8 bytes and 10 s above. The network sends one long message of the program at a time; the others wait their turn. Each long send ends with the result of its own session: a send that ended by its `TIMEOUT` while the kernel still runs its session lets the next one start, and that session's late end is given to no other send. When the network moves to another address (contention, Cannot Claim), a long send in progress ends with `ERROR_ID` 14 at once.
- **PGNs the network owns.** Request, Address Claimed, Acknowledgement, the transport protocol PGNs, DM1, DM2, DM3, DM11, DM13, DM22 and every `tx` PGN of the config end with `ERROR_ID` 4. With `"raw": { "program_override_protocol": true }` on the network the program may send the DM and `tx` PGNs (the log says so once per run); the others stay refused.
- **Receiving.** While `ENABLE` is TRUE, the bridge queues for `J1939_RECEIVE` up to `DEPTH` messages of its `PGN` (every PGN with `ALL_PGNS`) from its source, sent to the network's address or global (or to anyone with `ALL_DESTINATIONS`), reassembled when they came by the transport protocol. Each call takes one from the bridge's receive mailbox: `RECEIVED` TRUE with its fields, or `RECEIVED` FALSE with the last ones kept; `QUEUED` says how many still wait. A message longer than 8 bytes is read whole through a request mailbox (one round trip per 128 bytes) before `RECEIVED`. A message arriving at a full queue is dropped, counted in `DROPPED`, and `OVERFLOW` stays TRUE until `ENABLE` falls. Changing an input while enabled opens the receiver again with the new inputs. The network's own messages are not queued, and receivers change nothing for `rx` entries and requests in the config. A network has at most 16 J1939 receivers, and all networks together at most 32 receivers of any kind; a receiver whose messages wait unread for 1 s is closed (`ERROR_ID` 8, it opens again on the next call).
- **Requests.** `J1939_REQUEST` to an address is `DONE` with that ECU's first message of the PGN after the Request, sent to the network's address or to global (also when it is a 1785-byte one), and ends with `ERROR_ID` 12 and `ACK_CODE` (1 NACK, 2 access denied, 3 cannot respond) when it refuses; a positive acknowledgement is `DONE` with `LENGTH` 0. A global request is `DONE` once sent; the answers reach `J1939_RECEIVE` and the config's `rx` entries.
- **ECUs.** `J1939_ECU_INFO` gives the network's claim state, address and NAME and how many other ECUs it sees, from the bridge's network info (the first 8 networks), in the same call. `J1939_FIND_ECU` gives the lowest address whose ECU's NAME equals `NAME` in the bits set in `MASK` (`COUNT` says how many match); it asks the bridge again on every turn it gets while `ENABLE` is TRUE and sets `VALID` after the first answer.

ST functions, needing no bridge: `J1939_GET_BITS(DATA, START_BIT, BIT_LENGTH, SIGNED) : LINT` and `J1939_SET_BITS(DATA, START_BIT, BIT_LENGTH, VALUE) : BOOL` read and write a signal anywhere in the 1785 bytes, little-endian as J1939 sends signals (`BIT_LENGTH` 1..64; `J1939_SET_BITS` returns FALSE and writes nothing for bits outside the array). `J1939_NAME_MAKE` makes a NAME from its fields (`IDENTITY_NUMBER`, `MANUFACTURER_CODE`, `ECU_INSTANCE`, `FUNCTION_INSTANCE`, `ECU_FUNCTION`, `VEHICLE_SYSTEM`, `VEHICLE_SYSTEM_INSTANCE`, `INDUSTRY_GROUP`, `ARBITRARY_ADDRESS_CAPABLE`), and the block `J1939_NAME_SPLIT` splits one; they pack as the config's `ecu.name` does.

```
VAR
    info : J1939_RECEIVE;
    info_data : ARRAY[0..1784] OF BYTE;
    starts : LINT;
    ask : J1939_REQUEST;
    answer : ARRAY[0..1784] OF BYTE;
    ask_now : BOOL;
    cmd : J1939_SEND;
    cmd_data : ARRAY[0..1784] OF BYTE;
    send_now : BOOL;
    ok : BOOL;
END_VAR

(* ComponentInfo (PGN 65282, 40 bytes) from the engine at address 0. *)
info(ENABLE := TRUE, NETWORK := 0, PGN := 65282, SOURCE := 0, FILTER_SOURCE := TRUE, RX_DATA := info_data, LINK := canworks.link);
WHILE info.RECEIVED DO
    starts := J1939_GET_BITS(DATA := info_data, START_BIT := 32, BIT_LENGTH := 16, SIGNED := FALSE);
    info(ENABLE := TRUE, NETWORK := 0, PGN := 65282, SOURCE := 0, FILTER_SOURCE := TRUE, RX_DATA := info_data, LINK := canworks.link);
END_WHILE;

(* Ask for it now; the answer also reaches info. *)
ask(EXECUTE := ask_now, NETWORK := 0, PGN := 65282, DESTINATION := 0, DATA := answer, LINK := canworks.link);
IF ask.DONE OR ask.ERROR THEN ask_now := FALSE; END_IF;

(* 20 bytes of PGN 16#D000 to address 0, by RTS/CTS. *)
ok := J1939_SET_BITS(DATA := cmd_data, START_BIT := 0, BIT_LENGTH := 16, VALUE := 1500);
cmd(EXECUTE := send_now, NETWORK := 0, PGN := 16#D000, DESTINATION := 0, LENGTH := 20, DATA := cmd_data, LINK := canworks.link);
IF cmd.DONE OR cmd.ERROR THEN send_now := FALSE; END_IF;
```

### Error IDs

All J1939 blocks, the trouble code blocks included, use one table:

| `ERROR_ID` | Meaning |
|---|---|
| 1 | The network is not running |
| 2 | No such network |
| 3 | An input is invalid (`PGN` above 16#3FFFF, `LENGTH` above 1785, `DESTINATION` or `SOURCE` 254, `PRIORITY` above 7, `DEPTH` above 32, `SOURCE` above 253 for `J1939_DM_READ`) |
| 4 | The PGN is one the network sends itself (`J1939_SEND`) |
| 5 | Another DM2 read or clear for that address is pending (trouble code blocks) |
| 6 | No answer, or not sent, within `TIMEOUT` |
| 7 | The network is bus-off or its interface is down; a receiver stays open and shows it while it lasts |
| 8 | Cancelled by a PLC stop, a network restart, the bridge's watchdog or a bridge restart, or a receiver closed because its messages waited unread for 1 s |
| 9 | No free job (32 sends and requests across all networks) or receiver (16 per network, 32 in all) |
| 10 | The network is not a J1939 network |
| 11 | The network holds no address (claiming, or it cannot claim) |
| 12 | The destination refused: NACK, access denied or cannot respond (`ACK_CODE`) |
| 13 | No DM1 received from `SOURCE` yet (`J1939_DM_READ`) |
| 14 | The transport protocol session was aborted, or the network's address changed while it ran (`J1939_SEND`) |
| 20 | The bridge is not reachable (`canworks.ok` FALSE) |
| 22 | The config has no request mailbox, receive mailbox or network info that the block needs |

Blocks with `ENABLE` (`J1939_RECEIVE`) try again on every call after `ERROR_ID` 1, 7, 8, 9 or 20, so one enabled from the first scan opens once the network runs. A PLC stop ends every send and request with 8 and closes every receiver.

## The DBC file

`dbc` names the network's DBC file, relative to the config. The bridge does not read it; the configurator imports messages from it, the trace decodes with it and the simulator runs it. In the configurator, **Import DBC** on a J1939 network copies the file into the project's `canworks/` folder and turns the picked messages into `rx` or `tx` entries with free PLC locations ([configurator.md](configurator.md#j1939-networks)). `canworks-deploy --export-dbc` writes a J1939 network's `rx` and `tx` PGNs as a DBC with 29-bit identifiers.

## Simulator

`canworks-j1939-sim`, the J1939 simulator, plays one node of a DBC file on a SocketCAN interface or a USB adapter on the PC, for testing a PLC program without the other ECUs. CANopen devices have their own simulator, and J1939 networks do not run on the bridge's simulated bus; [simulator.md](simulator.md#why-two-simulators) says why and which simulator covers what. For example:

```sh
canworks-j1939-sim --dbc machine.dbc --node Engine --interface can1 --address 0
canworks-j1939-sim --dbc machine.dbc --node Engine --adapter slcan:COM5 --scenario engine.json --log engine.jsonl
canworks-j1939-sim --contend 128 --name-value 0x10 --interface can1     # take address 128 from the PLC
```

It claims its address, sends the node's messages at their DBC cycle time (`GenMsgCycleTime`) with values ramping between the signals' limits, or as a scenario file sets them, answers requests, and prints every message it receives decoded. A multiplexed message goes out as every page each cycle, or one page per cycle in turn with `--mux rotate`. `--help` describes the scenario format and the NAME options.

## Diagnostics and trace

With diagnostics on, `canworks-diag status --network machine` shows the claim state, address and NAME, the ECUs seen on the bus, each received PGN (sources, age, timeouts, raw signal values) and the counts of sent PGNs, answered requests and sent requests. Operations that only make sense for CANopen (SDO, NMT, LSS, parameters) are refused on a J1939 network.

`canworks-diag trace` and the configurator's **Trace** view decode a J1939 network's frames with its DBC: priority, PGN, source and destination, scaled values with units (for a multiplexed PGN the switch values, such as `Page=2`, and only that page's signals), address claims with their NAME fields, requests, acknowledgements and transport protocol sessions. `canworks-diag explain` and the frame inspector split a 29-bit identifier into its J1939 fields ([frame-inspector.md](frame-inspector.md)).

## Limits

- One J1939 network per interface; J1939 and CANopen cannot share an interface.
- Diagnostic messages cover DM1, DM2, DM3, DM11, DM13 and DM22 (see [Diagnostic messages](#diagnostic-messages)).
- Values are raw integers of up to 64 bits; floating point signals are not supported.
